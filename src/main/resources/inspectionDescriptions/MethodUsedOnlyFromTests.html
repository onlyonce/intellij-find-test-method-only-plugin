Reports methods declared in production source roots whose every caller lives in a test source root.

Such a method is production API kept alive only by the tests that assert on it. It inflates the public surface, blocks refactoring, and still counts as covered in coverage reports.

Example:


// src/main/java — reported
int calculateVatForLegacyRate(int net) { ... }   // only OrderServiceTest calls this

// src/test/java
void testLegacyVat() {
    assertEquals(119, service.calculateVatForLegacyRate(100));
}

A method with no callers at all is not reported here — that is plain dead code and belongs to the Unused declaration inspection.

Framework entry points are excluded through the platform's registered entry points and the Settings | Editor | Inspections | Entry points configuration, so Spring @Bean, @KafkaListener, @Scheduled and @EventListener methods, JPA no-arg constructors and Jackson accessors are left alone. Constructors, main, record accessors and methods overriding library declarations are also skipped.

Do not report methods annotated with is an editable list. It is seeded with two groups: annotations that mark a method as knowingly test-facing (@TestOnly, both @VisibleForTesting variants), and annotations that mark generated code (@Generated in its javax, jakarta and annotation-processing spellings, and Avro's @AvroGenerated). A method carrying one of them has either been acknowledged already or cannot be edited by hand, so reporting it is noise.

An annotation on the containing class counts for every method in it — which is what makes this effective on generated record and builder classes — and an annotation on an overridden declaration counts for its overrides. Remove entries to report annotated methods anyway, or add your own team's conventions and generators.

Code under a folder marked as a generated source root never reaches this inspection: the analysis scope excludes it outright. Generated code shows up here only when the project model does not know it is generated — usually because the build plugin registered the folder as an ordinary source root. Annotating is the fix; alternatively mark the folder as a generated source root in Project Structure | Modules.

This is a global inspection: run it via Analyze | Inspect Code with an analysis scope that includes test sources. With test sources excluded the inspection cannot tell a test-only method from a fully unused one, so it reports nothing.
